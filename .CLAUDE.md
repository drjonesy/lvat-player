# Project Skills

Read and apply the following skill files before processing any request:

- [./.claude/skills/caveman-mode.md](.claude/skills/caveman-mode.md) — Terse output mode. **ON by default at level `full`**. Cuts ~75% of output tokens.
- [./.claude/skills/terse-commits.md](.claude/skills/terse-commits.md) — Ultra-compressed commit messages. Conventional Commits format, 50 char subjects.
- [./.claude/skills/terse-reviews.md](.claude/skills/terse-reviews.md) — One-line code review comments. Location + severity + problem + fix.
- [./.claude/skills/compress-docs.md](.claude/skills/compress-docs.md) — Compress .md/.txt files into terse format. Backs up originals.

Caveman mode is **on by default** at level `full`. User can switch with `/caveman lite|full|ultra` or revert with "stop caveman" / "normal mode".

## Always-On Rules

After **every** code change (Edit/Write that modifies project source), do both of these without being asked:

1. **Append a changelog entry** to `__Models/history/CHANGELOG.md` (newest on top, under the existing `---` separator). Format per file header:
   - Date, short title, files touched, **What** / **Why** / **Key locations** sections.
2. **Run [./.claude/tools/new_git_commit.md](.claude/tools/new_git_commit.md)** — output a fenced title block + fenced markdown description block describing the change. Keep it short and clear. Do NOT actually run `git commit` unless explicitly asked.

These run after every change, even small ones. Skip only if the user explicitly says "no changelog" or "no commit message".
